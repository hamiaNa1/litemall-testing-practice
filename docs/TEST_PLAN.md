# 测试计划

目标：验证真实商城核心业务、接口鉴权和订单数据一致性，展示初级测试岗位所需的用例设计、执行、缺陷定位和Python回归能力。

需求依据：商城README、实际Vue页面、WxAuth/WxGoods/WxCart/WxOrder控制器、WxOrderService、MyBatis服务/Mapper和数据库schema。未取得外部产品需求书；接口错误码依据真实源码，权限隔离、正数量、商品与货品所属关系以及库存守恒作为独立业务约束。

## 测试范围和业务流

登录提取Token → 商品列表/搜索/详情 → 选择SKU → 加入购物车 → 收货地址 → 提交订单 → 查询待付款 → 取消 → 查询已取消。加购物车不预扣库存；下单101扣数量；取消102恢复数量；重复取消不能重复加库存。

正常场景：真实登录、商品搜索、购物车加/改/删、购买数量1/2、订单金额/明细/归属、列表页UI取消。异常场景：缺字段、空参数、错密码、无效Token、非法手机号、错验证码、空购物车、越权访问订单/购物车、商品货品错配。边界场景：购物车-1、0、1、2及库存+1，分页1、2、10。没有把分页无限大或所有字符串长度边界声称为已覆盖。

成功注册受短信依赖阻塞。短信关闭通过请求验证为701；测试账号由独立SQL fixture建立。微信登录、真实支付、退款、发货、超时自动取消、商品管理写操作和多浏览器兼容性不在本轮实际执行范围。

## 执行顺序

1. 查环境、源码依赖、SQL和启动流程；独立数据库和真实后端健康检查。
2. P0程序驱动业务功能检查和SQL验证；Postman/Newman订单集合。
3. pytest正常/异常/边界接口测试，保留真实失败断言。
4. Playwright真实页面交互，POM封装，截图、Trace和Allure。
5. 重复回归、清理核验和证据整理。

功能执行包含API驱动业务检查和真实UI操作；没有声称用户或人工测试员手工执行过所有CSV行。每个实际执行行可追溯到JSON/JUnit和代码断言。

## 测试环境与数据

Windows、Python3.10、Java8、SpringBoot2.1.5、MySQL8.4。后端8080、Vue6255、独立MySQL13306，均绑定loopback。单进程顺序执行写测试，不支持共享种子库存下直接pytest-xdist并行。

fixture按函数创建唯一qa_run_用户；商品读种子货品1，保存库存基线；地址通过真实接口创建。teardown先取消待付款订单恢复库存，再按已知用户ID删除测试记录，并确认账号消失和库存回到基线。失败也清理。日志脱敏；敏感.env不提交。

## 判定与交付

接口同时断言HTTP200、整数errno、errmsg和业务数据。业务错误采用HTTP200+非零errno，不能把errno401/502误写成HTTP401/502。SQL核对订单状态、金额、明细、所属用户、购物车deleted和库存。

失败分为测试代码、环境或商城缺陷，分别记录。商城缺陷保留defect marker，完整运行应显示失败；正常回归显式deselect，不能换成通过或使用xfail掩盖。商城业务源码不修复，回归状态如实写未修复/仍失败。

交付：测试用例、Postman集合、Python/Playwright代码、SQL、Allure、4项缺陷证据、Windows操作文档和面试资料。
